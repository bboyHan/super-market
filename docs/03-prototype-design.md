## 三、核心交易流程（原型重点）

交互式 HTML 原型 `04-trading-prototype.html` 模拟以下完整流程：

```
Step 1: API支付商下单
  ───────────────
  API 支付商 "商户A" 调用 API 购买 "京东E卡100元" × 1
  订单状态: SUBMITTED → PENDING
  
Step 2: 供应商确认收款
  ───────────────
  供应商登录后台 → 订单管理 → 待确认列表
  点击"确认收款" → 系统冻结代理商积分 → 触发交付
  订单状态: PENDING → DELIVERING

Step 3: 代理商交付
  ───────────────
  代理商收到交付指令 → 系统自动发卡密 → 交付完成
  订单状态: DELIVERING → SUCCESS

Step 4: API支付商收到回调
  ───────────────
  平台 POST 回调到 notify_url
  内容包含: 订单号、状态、交付内容(卡密)
  
Step 5: 对账
  ───────────────
  供应商查看对账看板:
  - 按 API 支付商维度: 商户A 今日 +1 单
  - 按品类维度: 京东卡 今日 +1
```

## 四、页面流转关系

```
API 支付商（外部）
    │
    │ API下单
    ▼
供应商后台 ──→ 订单管理（待确认列表）
    │              │
    │        点击"确认收款"
    │              │
    ▼              ▼
  已完成订单     代理商后台（待交付列表）
    │              │
    │        自动交付
    │              │
    ▼              ▼
  回调通知     对账看板更新
  API支付商     (日结统计数据刷新)
```
