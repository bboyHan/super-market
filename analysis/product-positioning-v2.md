# 神谕 (Oracle) — 产品定位与架构方案 v2.0

## 一句话定位

> **万能数据采集器：从任意应用（浏览器/QQ/端游/小程序）中提取有价值的数据，无需应用配合、无需用户配置。**

## 核心价值

不是抓包工具，是**数据采集器**。抓包是手段，提取数据是目的。用户在意的不是"看到 HTTPS 包"，而是"拿到了支付链接、聊天记录、订单信息"。

## 目标用户

| 用户 | 需求 | 使用方式 |
|------|------|---------|
| 代理商 | 采集支付凭证到平台 | 一键启动，后台运行 |
| 数据分析者 | 获取应用通信数据 | 配置规则，自动提取 |
| 安全研究者 | 了解应用通信行为 | 调试模式，查看原始数据 |

## 数据来源矩阵

```
介质        方案          状态    用户配置
────────────────────────────────────────
浏览器      CONNECT 代理  🟢 可用  设代理
PC QQ       hosts + MITM  🟡 可行  需知域名
端游        hosts + MITM  🟡 可行  需知域名
微信小程序  TUN 虚拟网卡   🔧 规划  零配置
抖音小程序  TUN 虚拟网卡   🔧 规划  零配置
手机热点    TUN + 转发    🔧 规划  零配置
```

## 三层架构

```
通道层（采集）
  自动选择最佳捕获方式
  A: CONNECT → B: hosts → C: TUN

解析层（提取）
  platforms/*.json 定义规则
  任意平台、任意数据格式

输出层（上报）
  现有 Pipeline → 工具端 → 平台端
```

## 当前工作重点

**SNIFF + hosts 方案跑通**：
1. SNIFF 监控流量，实时展示域名（已实现）
2. 用户确认要拦截的域名
3. 自动写入 hosts 并启动 MITM
4. Pipeline 提取数据 → 工具端 → 平台端

TUN 作为 Phase 3，等 hosts 方案积累足够域名后再上。
